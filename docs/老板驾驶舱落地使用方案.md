# 老板驾驶舱落地使用方案

> **目的**：把 `workshop-app` 已上线的「老板驾驶舱」（P9 只读端 + P13 资金往来汇总）从"能看的原型/演示"变成老板**每日经营决策的入口**，真正用进业务流。
> **写法约定**：文中标记【已具备】为系统当前已实现能力；【建议增强】为让驾驶舱"真正用起来"所需的小改动，便于区分现状与目标，避免空谈。

---

## 1. 系统现状：驾驶舱现在能做什么

「老板驾驶舱」是车间 ERP 的**只读汇总端**，所有数字实时取自生产报工 / 库存 / 财务台账，非人工填报。当前模块与数据接口如下：

| 模块 | 展示内容 | 数据接口（实时） | 状态 |
|---|---|---|---|
| 核心指标卡 | 今日产量、本月产量、在职人数、低于安全库存数 | `/api/stats/summary` | 【已具备】 |
| 月度产量趋势 | 近 6 个月产量柱图 | `/api/stats/production` | 【已具备】 |
| 库存预警明细 | 低于安全库存的物料清单（名称/编码/当前/安全线） | `/api/materials`（筛 `is_low`） | 【已具备】 |
| 收支净额 | 收入合计 / 支出合计 / 净额 | `/api/finance`（台账） | 【已具备】 |
| 资金往来 | 应收未收 / 应付未付 / 净占用 | `/api/ar/summary/by-customer` + `/api/ap/summary/by-supplier` | 【已具备】 |

**权限与可达性【已具备】**：仅「老板」「管理」角色可见（`app.js` 的 `PAGE_ROLES`）；全局 `requireAuth`（P11 真登录）须经账号进入；内网/手机局域网浏览器直开即可，无需安装 App。
**核心卖点【已具备】**：老板看到的数字 = 车间正在发生的业务，天然可信，这是它区别于"另做 Excel 报表"的根本价值。

## 2. 实际应用场景（绑定真实业务节奏）

按"谁·何时·看什么·做什么"设计，让驾驶舱嵌入既有工作流，而非另起炉灶。

**场景 1｜晨会第一屏（每日 08:30）**
老板/管理用手机或车间电脑打开驾驶舱 → 看今日产量、本月产量、库存预警。若库存预警出现红色项，**当场指派采购/领料**，不等会后。

**场景 2｜资金周会（每周固定）**
看「应收未收 / 应付未付 / 净占用」→ 判断现金流压力，决定本周催收回款节奏与付款安排，避免拍脑袋。

**场景 3｜巡线随时看（车间走动）**
手机连车间局域网直开，走动中看实时产量与异常，不必回办公室查电脑，问题早发现。

**场景 4｜月底经营复盘（每月末）**
月度产量趋势 + 收支净额 → 当月是否达标、毛利走向如何，作为经营会唯一数据底稿。

**场景 5｜异常响应（事件驱动）**
库存低于安全线 → 触发补料/采购；应收长期挂账 → 指派跟单催收。驾驶舱负责"发现"，运营页负责"处理"，形成闭环。

---

## 3. 操作流程

### 给老板的极简三步
1. **登录**：手机/电脑浏览器打开车间局域网地址，用老板账号登录（P11）。
2. **看首屏**：一屏看完全厂生产、库存、资金全貌，红字即异常。
3. **下钻 / 派单**：点异常卡片跳到对应运营页处理，或口头指派责任人。

### 给管理的标准流
登录 → 驾驶舱总览发现异常 → 下钻到运营页（采购计划 / 生产任务单 / 资金往来）→ 处理并回到驾驶舱确认状态变化。

## 4. 关键功能模块设计

### 4.1 核心指标看板【已具备】
六大区一屏聚合：生产（产量）、人力（在职）、库存（预警）、财务（收支净额）、资金往来（应收/应付/净占用）、趋势（月度产量）。设计原则：**一屏看全厂，红即异常，不堆砌**。

### 4.2 数据钻取【当前为汇总，建议增强】
**现状**：各卡片目前为只读数字，**暂无点击下钻**——这是它"停留在看板"的关键短板。
**建议增强（小改动，复用现有页面，零新表）**：把卡片/区块设为可点击，跳转对应运营页，让"看到异常→一点即到处理页"：

| 驾驶舱区块 | 点击跳转到 |
|---|---|
| 今日产量 / 本月产量 | 报表中心·生产报表（或生产任务单） |
| 库存预警明细 | 原料库存页（`materials`） |
| 收入 / 支出 / 净额 | 报表中心·财务报表 |
| 应收未收 | 资金往来·应收（`ar`） |
| 应付未付 | 资金往来·应付（`ap`） |
| 月度产量趋势柱 | 报表中心·生产报表 |

> 该增强仅改 `public/js/pages/boss.js` 的卡片渲染（加 `onclick` 调用 `navigate(...)`），工作量小、风险低，却是"真正用起来"的开关。

### 4.3 权限控制【已具备】
- **P11 真 RBAC**：「老板/管理」看全部数据；「跟单/销售」仅见归属客户（`visibleCustomerIds` 隔离），且**无驾驶舱入口**。
- **只读无写**：驾驶舱端无任何编辑操作，杜绝老板误改业务数据。
- **安全建议**：若需手机**外网**访问，必须走登录 + HTTPS / 内网穿透并绑定设备，**不在公网裸奔**。

### 4.4 移动端只读【已具备】
手机浏览器直开局域网地址即可，响应式布局，适合巡线场景，无需开发独立 App。

### 4.5 数据可信与实时【已具备，核心卖点】
数字来自报工、出入库、收付款等真实业务流自动汇总，**非人工日报**。这是驾驶舱能替代微信群截图/Excel 的根本原因，也是推广时最该向老板强调的点。

## 5. 上线推广步骤（让驾驶舱真正用起来）

### 阶段 0｜准备（上线前 1 周）
- [ ] 开通「老板」「管理」账号（P11），**改默认密码**，手机添加驾驶舱书签/桌面快捷方式。
- [ ] 确认车间电脑、手机与服务器同局域网，首屏地址可达。
- [ ] **校准口径**：产量单位、安全库存线是否设对（错的安全线会让预警失效）。
- [ ] 指定一名「驾驶舱负责人」（管理角色）日常维护基础资料与数据质量。

### 阶段 1｜试点嵌入晨会（第 1–2 周）
- 把"每天 08:30 先看一眼驾驶舱"写进**晨会 SOP**，替代口头汇报。
- 硬约束：库存预警有红 → 当场定责任人；产量异常 → 当场问原因。
- 目标：让老板形成"**先看屏、再开会**"的肌肉记忆。

### 阶段 2｜异常即响应（第 3–4 周）
- 把驾驶舱异常**转化为动作**：库存预警 → 建采购计划/领料单；应收超期 → 派跟单催收。
- 用现有运营页承接，驾驶舱只做"发现"，运营页做"处理"，闭环跑通。
- 建议同步上线 4.2 钻取增强，让"发现→处理"一键可达。

### 阶段 3｜推广到管理层 / 股东（第 2 月）
- 管理角色日常用驾驶舱做过程管理。
- 月底经营会**只用驾驶舱数据**复盘，停止另做 Excel 报表（否则两套数据必分歧）。

### 阶段 4｜复盘迭代（持续）
- 每月收集"还缺什么指标"，小步增强（如目标对比线、Top 客户应收）。
- **防退化**：把"以驾驶舱数据为准"写入制度，避免回到微信群截图。

### 关键成功要素（防"演示即终点"）
1. **绑定固定动作**（晨会必看），而非"有空再看"。
2. **异常必须跟出动作**，否则驾驶舱沦为墙上装饰。
3. **数据质量有人负责**（管理角色维护基础资料/安全库存）。
4. **老板亲自用**，上行下效；老板不用，全员不用。

## 6. 风险与对策

| 风险 | 表现 | 对策 |
|---|---|---|
| 数据不准 → 老板不信 | 安全库存未设、基础资料错 | 阶段 0 校准 + 管理角色日常维护 |
| 网络不可达 → 晨会卡壳 | 服务器/局域网抖动 | 车间电脑常开 + 手机局域网备选双保险 |
| 只看好看不用 → 退化 | 看完无动作 | 阶段 2 异常即响应硬约束 |
| 外网安全风险 | 公网裸奔被爬 | 内网/登录 + HTTPS，不暴露公网 |

## 8. 后续增强建议（让驾驶舱越用越深）

1. **钻取深化**：卡片 → 运营页（见 4.2），打通"发现→处理"最后一公里。
2. **预警推送**：库存/应收超阈值触发企业微信/短信提醒，不等老板主动看。
3. **目标对比**：产量/回款叠加月度目标线，红绿一眼知达标。
4. **经营快照**：一键导出当日/当月 PNG/PDF，直接发老板微信，替代口头播报。

> 以上增强均可在不新增数据表的前提下，基于现有接口与页面小步迭代，符合"离线零依赖、实时派生不冗余"的整体设计原则。
