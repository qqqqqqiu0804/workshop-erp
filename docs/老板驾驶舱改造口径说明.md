# 老板驾驶舱改造 —— 业务口径说明（拍板版）

> 2026-09-09 由老板拍板（微信转述），Agent 记录固化。**此后所有驾驶舱/报表的产量、合格率、班次、半成品计算一律以本文为准**；改口径必须先改本文再改代码。
> 对应评审文档：阶段 3 的前置条件（§3.2 五个歧义）已全部关闭。

## 1. 计划达成率 —— 成品口径 ✅

- **分子**：实际产量 = 成品口径（末道工序去重，复用 `finishedRowsSubquery()`）。
- **分母**：计划产量，来源优先级：`production_tasks.plan_qty`（成品任务计划）→ `task_operations.planned_qty`（工序计划，仅末道工序计入成品口径）。**不新建计划表**。
- 展示：完成 = 绿，未完成 = 红。**禁止**用工序加工量做分子（会是成品量的 3–4 倍，达成率虚高）。

## 2. 合格率分母 —— 完工数 ✅

- **合格率 = 合格数 ÷ 完工数**（成品口径完工量），**不是** ÷ 检验批次量（`quality_checks.qty_check`）。
- 不良率 = 不合格数（`qty_ng`）÷ 完工数。
- 检验数据不全时（完工了但没检），合格率按已检部分算，页面标注「按已检数据」。

## 3. 白班 / 夜班 —— 时间边界 ✅

- **白班：08:00 – 20:30；夜班：20:00 – 次日 08:00**。20:00–20:30 为交接重叠段。
- 实现：`production_log` 新增 `shift` 列（`白班` / `夜班` / NULL=未分班），**录入报工时选择**；
  录入默认值按报工时间自动推断：`[08:00, 20:00)` → 白班，`[20:00, 次日 08:00)` → 夜班；**交接重叠段（20:00–20:30）由人工选择覆盖**。
- 历史数据 `shift` 为 NULL → 统计中单列「未分班」，不臆测归班。
- 报工页下拉增加班次选择（默认自动推断值，可改）。

## 4. 加工时长 / 每班产能 —— 本期不做 ✅

- 数据库无此数据，**不人工维护、不加字段**。需求清单中"加工时长(2.03)、每班产能(290)"两列暂缺，驾驶舱今日明细不含这两列。
- 未来如需启用：`products` 加 `cycle_sec` / `shift_capacity` 字段 + 人工维护页，届时再评。

## 5. 半成品（WIP）计量点 ✅

- **定义：做完任何一个工序、但尚未完成全部工序的数量，都算半成品。**
- 派生公式（实时 SQL，不落库）：
  `半成品 = max(0, min(各非末道工序的累计报工量) − 末道工序累计报工量)`
- 与成品口径的关系：成品 = 末道工序累计（去重）；半成品与成品相加 = 首道投入口径的近似上限，两者不重复计算。
- 展示位置：驾驶舱「库存物资」卡的半成品行（数值口径为**数量**，非会计 1409 的金额口径；会计口径仍以凭证为准）。

## 6. 附加确认（沿用 9-08 拍板）

| 项 | 结论 |
|---|---|
| 历史追溯 | 月度快照表 + 永久冷备（不做全库软删除）；快照表为全项目**唯一豁免的冗余存储** |

| 驾驶舱 | 只读无写铁律不破；「提醒」一律跳转运营页 |
| 图表 | 不引库，`UI.lineChart()` 内联 SVG |
