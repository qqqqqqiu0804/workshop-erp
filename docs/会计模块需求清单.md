## 二、核心工程决策（必读，决定整套系统骨架）

### 2.1 复式借贷记账（必须做，与柠檬云对齐）
- **借贷记账** = 每笔账同时记"借方" + "贷方"，且借贷必相等。这是会计的基石（资产 = 负债 + 权益）。
- 现有 `finance_ledger` 是**单式**（一条记录一个金额），只能记录流水，不能做账簿报表。
- **必须新增完整借贷凭证表**：`accounting_vouchers`（凭证主档）+ `accounting_voucher_lines`（分录行）。

### 2.2 会计科目体系（必须做，骨架）
- 新增 `accounting_subjects`（科目主档）—— 5 大类：
  - **1xxx 资产类**（现金/银行/应收/存货/固定资产等）
  - **2xxx 负债类**（应付/借款等）
  - **3xxx 所有者权益类**（实收资本/本年利润/利润分配等）
  - **4xxx 成本类**（生产成本/制造费用等）
  - **5xxx 损益类**（收入/费用，结转损益用）
- 字段：`code`（4 位数字编码）、`name`、`parent_code`（支持多级科目树）、`category`、`balance_direction`（借/贷）、`is_aux_customer`（辅助核算-客户）、`is_aux_supplier`、`is_aux_dept`、`is_aux_project`、`is_active`、`level`（1-4）
- **预置科目**：标准小企业科目表（~60 条），用户可增删改。

### 2.3 辅助核算（必须做，柠檬云标配）
- 柠檬云的"核算项目明细账 / 余额表 / 组合表"全靠辅助核算。预置 4 类：
  - **客户辅助核算**：1 个客户 = 1 个辅助对象，挂应收科目（如 1122 应收账款）
  - **供应商辅助核算**：1 个供应商 = 1 个辅助对象，挂应付科目（如 2202 应付账款）
  - **部门辅助核算**：可选 v1 实现（5 部门：生产/品检/包装/管理/采购）
  - **项目辅助核算**：v1 不做（工厂用不到项目核算）
- **数据模型**：`aux_*` 4 张表 + 凭证分录行的 `aux_*_id` 字段。

### 2.4 会计期间（必须做，制度）
- 新增 `fiscal_periods`：自然月，状态 `开放 / 已锁定`，硬锁（锁定后老板也不能改，要"反锁定"才可改）。
- v0.1 已规划，v1 升级为**强制制度**：所有写财务接口必须校验期间。

### 2.5 数量金额核算（必须做，五金厂刚需）
- 工厂有大量"件/kg/米/卷"计量。**部分科目**（如原材料/库存商品/产成品）需要"数量 + 单价 + 金额"三栏。
- 新增字段：`quantity`（数量）、`unit_price`（单价）、`amount`（金额）= 数量 × 单价
- 凭证分录行同时记录数量金额。

### 2.6 外币核算（v1 不做，工厂纯人民币）
- 柠檬云有，但工厂出口走的是收汇人民币结算（客户类型 `国外` 但入账仍是人民币）。**v1 不做**。

### 2.7 多账簿（v1 只做一本总账）
- 柠檬云有"管理账簿 / 税务账簿"切换。**v1 只做一本账**（小企业够用）。

### 2.8 跨期间调整（v1 不做）
- 柠檬云有"以前年度损益调整"。**v1 不做**，留给 v2。

### 2.9 数量辅助（v1 不做）
- 柠檬云有"数量辅助"独立核算。**v1 不做**，合并到科目级数量金额。

### 2.10 期末结转（必须做，核心）
- **月度结转**：损益类科目（5xxx 收入/费用）月末余额 → "本年利润"（3103）。
- **年度结转**：年末"本年利润" → "利润分配"（3104）。
- **结转生成自动凭证**：由用户在"期末结转"页点按钮，系统生成一张"结转凭证"。

### 2.11 资产卡片 + 折旧（必须做）
- 现有 `machines` 表借用做"固定资产"，**新建** `fixed_assets` 独立表（不污染 machines）。
- 折旧方法：v1 支持**直线法**（常用）+ **双倍余额递减法**。
- 折旧自动生成凭证：每月折旧计算后，自动写入"管理费用/制造费用-折旧" + "累计折旧"借贷分录。

### 2.12 工资与社保（必须做）
- 工资从现有 `employees` + `production_log`（产量×工价）派生。
- 社保（五险一金）v1 做**配置 + 计算**，不实际代扣代缴（让代账会计做）。

### 2.13 发票模块（必须做，独立子模块）
- 销项发票 = 销售开票（已有 `ar_invoices` 类似物，独立化为销项发票表）；
- 进项发票 = 采购发票（已有 `purchase_invoices`）；
- 费用单据 = 报销类（v1 简化为"通用费用单据"）；
- **一键取票 / 银企互联 / 发票风险分析**：这些是柠檬云 SaaS 对接外部税控/银行的能力，**工厂内网离线版做不到**，v1 改为**模板导入 + 手动核查**。

### 2.14 收票宝（柠檬云特色，简化做）
- 柠檬云的"收票宝"是把发票扫描件归档到云端。本系统**排除电子档案**，所以**收票宝只做台账记录**（票号/金额/税率/销方），不做 PDF/OFD 存储。

## 四、统一架构与设计原则

### 4.1 会计期间（核心制度）
1. **硬锁**：期间锁定后任何人都不能改（包括老板/管理），需"反锁定"才可改。
2. **自动生成期间**：首次启用系统按自然月生成 12 期。
3. **凭证必须落在期间内**：期间外凭证直接 400 拒绝。
4. **结账检查**：锁定期间前自动检查 8 项（凭证是否平衡/是否审核/库存/往来核销/折旧/工资/资产）。

### 4.2 借贷平衡（核心约束）
- 每张凭证借贷必相等（差额 = 0），否则**保存时报错**。
- 数据库约束：`CHECK (total_debit = total_credit)`。
- 录入界面实时显示差额，红字提示。

### 4.3 数量金额核算
- 部分科目标记 `is_quantity`，凭证分录行同时记录 `quantity/unit_price/amount`。
- 自动校验：`amount = quantity × unit_price`（小数容忍 0.01）。

### 4.4 辅助核算
- 辅助类别在科目设置里勾选（如"1122 应收账款"勾客户辅助）。
- 凭证分录行的辅助对象必填（如挂了客户辅助，必须选客户）。
- 辅助账簿按辅助对象查询。

### 4.5 RBAC（8 角色 × 30 子模块）
详见第六节权限矩阵。**核心规则**：
- **写权限**默认 `[老板, 管理]`，与现有 `finance/ar/ap` 一致。
- **读权限**部分放开给其他角色（如采购读供应商辅助、工程读存货辅助）。
- **菜单可见性**按角色 + 资源组合控制。
- **不可绕过**：任何人都不能绕过期间锁定/借贷平衡/RBAC。

### 4.6 数据来源（尽量复用，不重做）
| 现有对象 | 会计模块用法 |
|---|---|
| `finance_ledger` | 标记为"旧版只读"，数据迁移到新凭证表（一次性脚本） |
| `ar_invoices` / `ar_receipts` | 升级：增加 `subject_code`、`aux_customer_id` |

## 十、需要用户拍板的 12 个决策点

> 在动手出方案/排期之前，先回答这 12 个问题（有选项的建议直接选）。

1. **复式借贷记账做不做？**
   - ✅ **必做**（你已要求对齐柠檬云，借贷是会计基础）
   - 工作量：M0 必做，约 4-6 周
2. **会计科目体系按什么标准？**
   - A. 小企业会计准则（推荐，工厂适用）
   - B. 企业会计准则
   - C. 自定义（用户全管）
   - **建议**：A
3. **辅助核算范围？**
   - A. 客户+供应商（最小，推荐）
   - B. 客户+供应商+部门（标准）
   - C. 全部 4 类（含项目，工厂用不到）
   - **建议**：B
4. **数量金额核算？**
   - A. 部分科目（原材料/库存商品/产成品）启用数量金额
   - B. 所有科目启用（性能开销大）
   - C. 不启用（只金额）
   - **建议**：A
5. **期间锁定是硬锁还是软锁？**
   - A. 硬锁（推荐，财务严肃性，柠檬云也是）
   - B. 软锁（老板永远可改）
   - **建议**：A
6. **多账簿 / 多公司？**
   - A. 不做（推荐，工厂够用）

   - **建议**：A
7. **银企互联真实对接？**
   - A. 不做（推荐，柠檬云那个要银行 API 授权，工厂用不到）
   - B. 手工导入银行流水 + 自动匹配
   - **建议**：B（M4）
8. **一键报税做不做？**
   - A. 不做（强烈推荐，合规风险，让代账会计做）
   - B. 申报辅助（生成申报数据但不入税务局系统）

   - A. 简化版（累计预扣法估算，不扣到分）

    - **建议**：A
11. **发票风险分析做多深？**

    - **建议**：A

    - **建议**：A 或 C（M2+ 不急）

### 11.2 合规风险（必须明确）

| 风险 | 应对 |
|---|---|
| 老板拿本系统数字去报税出错 | 报表页明确标注"非合规报表"；一键报税不做 |
| 五险一金算错导致员工投诉 | 工资模块标注"参考用，最终以社保局/公积金中心核算为准" |
| 折旧方法选错导致税务调整 | 提供税务折旧方法（直线法，残值率5%）默认；自定义方法需老板确认 |
| 老板用本系统直接开发票 | 销项发票模块只做"登记"，不开真票（真票仍用开票软件） |

### 11.3 备选方案（如整体推不动）

- **A. 简化版**：只做 M0 + M1（凭证+账簿+资金），其他全部不做。约 2-3 个月。
- **B. 外包版**：M2-M4 外包给会计软件开发商（柠檬云/金蝶/用友都有），本系统保留 M0 + M1 + 对接接口。
- **C. 推迟版**：M2+ 等你寒假回来或下学期再做。
