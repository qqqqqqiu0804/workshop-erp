## 〇、背景与定位（一句话）

基于柠檬云模板、排除电子档案，把一套**完整复式借贷会计系统**作为工作台的一级菜单"会计"集成进来；存储用独立 `data/accounting.db`，由同一 `WorkshopERP` 服务加载（见架构决策分析结论）。**全量 M0–M5 由本人完成**，不移交第三方；回校后通过闲置机（192.168.1.8:3100）+ UU 远程 + GitHub private 仓库 + README 第八节二次迁移 SOP **远程继续推进**。

## 一、推行原则（硬约束）

1. **决策先行**：每个阶段启动前，必须先关闭该阶段的"决策门禁"（见第二节），不拍板不动手。
2. **旧账不破坏**：现有 `finance_ledger / ar_* / ap_*` 全部保留，新模块启用后进入**双写过渡期**，至 M4 才正式切换。
3. **派生数据实时算**：余额、试算平衡、报表均由 SQL 实时计算，不冗余落库（与现有 `workshop.db` 原则一致）。
4. **RBAC 不松动**：会计菜单仅对 老板 / 管理 角色可见（**无代账角色**，用户明确不用）；操作员、品检、销售、跟单、采购、工程 不可见、且 `/api/accounting` 读接口也 403（连看都不能看）。
5. **每阶段闭环**：入口决策 → 开发 → 退出验证（DoD）→ 才进下一阶段。
6. **回滚预案**：每个阶段开始前先 `VACUUM INTO` 备份 `workshop.db` 与新建的 `accounting.db`。

## 三、分阶段推行路线图（M0–M5）

每个阶段含：目标 / 子模块 / 交付物 / 入口决策 / 退出标准(DoD) / 风险 / 验证 / 周期。

### M0 — 会计核心骨架 ✅ 已完成（2026-09-04）

- **状态**：已交付并验收通过——`db_accounting.js`（建库+64 条科目模板）+ `routes/accounting/*` + 会计页 + 9 条 M0 测试；全套件 **136/136 全绿**。功能明细见 `docs/功能清单-当前版本.md` 第八节，编码骨架见 `docs/骨架.md`。
- **目标**：搭好复式记账地基，能录凭证、看科目余额、关账。
- **子模块**：科目表（5 大类 + 辅助核算）、会计期间、借贷凭证录入/审核/记账、期初余额录入、试算平衡、凭证查询。
- **交付物**：`data/accounting.db` 建库脚本、`routes/accounting/*` 接口骨架、凭证录入页、科目余额表页、期初录入页、~30 个测试用例。
- **入口决策**：关闭 1/2/3/4/5/6。
- **退出标准(DoD)**：
  - 能建科目、录一笔"借:银行存款 贷:实收资本"并审核记账；
  - 凭证借贷必相等（后端强校验，不等拒存）；
  - 科目余额表借=贷（试算平衡通过）；
  - 关账后改凭证被拒、需反结账。
- **风险**：科目体系设计错 → 期初导不进。缓解：先用模板科目表，允许 M0 内调整。
- **验证**：本机 `PORT=3100 npm start` + 浏览器走一遍录凭证→记账→余额表。
- **周期**：4–6 周。

### M1 — 账簿与基础报表 ✅ 已完成（2026-09-04）

- **状态**：已交付并验收通过——`routes/accounting/ledgers.js`（总账/明细账/日记账/现金·银行·数量金额账）+ `routes/accounting/reports.js`（资产负债表/利润表）+ `routes/accounting/periods.js` 期末结转 + 会计页「账簿」「报表」tab + 6 条 M1 测试；全套件 **142/142 全绿**。
- **目标**：从凭证自动生成标准账簿，出两张主表。
- **子模块**：总账、明细账、日记账、现金日记账、银行日记账、数量金额账、期末结转（损益→本年利润，12 月再→利润分配）、资产负债表、利润表。（多栏账全量、现金流量表留待 M4。）
- **交付物**：6 类账簿接口 + 期末结转接口 + 2 张报表接口 + 会计页账簿/报表视图 + 6 条 M1 测试。
- **入口决策**：M0 DoD 通过。
- **退出标准(DoD)**：账簿与凭证一致（实时 SQL 算，改凭证账簿同步变）；资产负债表 `balanced=true` 且 资产=负债+权益；利润表本期/本年累计正确；期末损益结转后本年利润归零、12 月再结转至利润分配。
- **风险**：结转逻辑错导致报表不平。缓解：M1 用"手工结转按钮"生成转字草稿，需审核+记账生效，不自动。
- **验证**：`buildMonth` 录一个月凭证→结转→出表，与手工核算（资产 145000 / 净利 15000 / 利润分配 15000）一致，6/6 通过。
- **周期**：4–6 周。

### M2 — 发票与资金深化 ✅ 已完成（2026-09-04）

- **状态**：已交付并验收通过——`routes/accounting/invoices.js`（销项/进项/费用发票登记 + 一键生成应收/应付/费用凭证 + 风险扫描 + 资金一览）+ `routes/accounting/bank.js`（银企流水导入 + 自动匹配未达账）+ 会计页「发票」tab（6 子视图）+ 8 条 M2 测试；全套件 **150/150 全绿**。
- **目标**：发票登记与凭证联动、风险扫描、资金一览、银企流水导入匹配。
- **子模块**：销项发票、进项发票、费用单据、发票风险分析(简：重复号/税额异常/逾期)、资金一览（销项/进项汇总 + 按客商分组）、银企流水导入+自动匹配未达账。
- **交付物**：`db_accounting.js` 新增 5 张 M2 表（sales_invoices / purchase_invoices_v2 / expense_vouchers / invoice_risk_logs / bank_statements）+ 发票与银企接口 + 会计页发票视图 + 8 条 M2 测试。
- **入口决策**：关闭 7/11（按建议方案：导入流水+自动匹配、简化版风险分析）。
- **退出标准(DoD)**：
  - 发票登记后能一键生成凭证，分录自动带出（销项：借 1122 贷 5001+2221；进项：借 1403+2221 贷 2202；费用：借费用 贷银行，费用科目带部门辅助），借贷必相等、关账期间拒生成；
  - 风险扫描能识别重复票号 / 税率异常（>13% 或 <3%）/ 逾期；
  - 银企流水导入后能自动匹配未达账（流水借=银行支出匹配凭证明细 credit 1002；贷=银行收入匹配 debit 1002；金额相等且 10 日内）；
  - 资金一览销项/进项汇总与按客商分组正确。
- **风险**：发票→凭证联动分录错。缓解：生成凭证为「转」字草稿，需审核+记账生效，不自动入账簿。
- **验证**：8/8 用例通过（含非财务角色读 403、关账期间拒生成凭证）。
- **周期**：3–4 周（实际本机完成）。

## 四、数据迁移计划（旧 → 新）

### 4.1 现状（保留不删）
- `finance_ledger`（单式：收入/支出/余额）
- `ar_invoices` `ar_receipts` `ap_invoices` `ap_payments` `purchase_invoices`

### 4.2 目标
- `accounting.db`：`accounts`(科目) / `accounting_periods`(期间) / `vouchers`(凭证头) / `voucher_entries`(分录) / `account_balances`(期间余额) / `aux_`(辅助核算) 等。

### 4.3 映射（M4 执行）
| 旧 | 新 |
|---|---|
| `ar_invoices.so_id / amount` | 应收凭证（借:应收账款-客户 贷:主营业务收入） |
| `ap_invoices.po_id / amount` | 应付凭证（借:原材料 贷:应付账款-供应商） |
| `finance_ledger` 余额 | 科目期初余额 |
| `ar_receipts` / `ap_payments` | 收付款凭证 |

### 4.4 过渡策略
- **M0 起**：新凭证写入 `accounting.db`，旧表继续接收业务系统写入（双写），旧表保持只读查询至 M4。
- **期初导入**：M0 用现有应收/应付余额 + 资金余额填科目期初。
- **M4 切换**：校验新旧余额一致 → 旧表标记 `deprecated` 只读 → 新表为唯一真相源。
- **回滚**：任一阶段出错，用 `VACUUM INTO` 备份恢复，旧表始终保留。
