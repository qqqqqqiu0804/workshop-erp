# 本地化部署方案（车间内网）

> 适用场景：经费未批、暂不上云；在车间局域网内一台常开 PC（当前为开发笔记本临时顶替，9/5 开学后失效）运行，车间电脑/平板通过局域网 IP 访问。应用零外部依赖、数据全在本机 SQLite，不依赖外网。

## 一、环境要求
- Node.js 22+（需内置 `node:sqlite`，Node 20 无此模块）。建议使用本机 managed Node 22：
  `C:\Users\HXT\.workbuddy\binaries\node\versions\22.22.2\node.exe`
- 端口：默认 3000；**本机 3000 被 Mineradio.exe 占用，统一用 3100**。干净车间 PC 上可直接用 3000。

## 二、一键启动（推荐给车间）
双击项目根目录的 **`start-local.bat`** 即可：
1. 探测并使用 managed Node 22；
2. 执行 `npm run build:pages`（生成 `public/js/pages/pages.bundle.js`）；
3. 后台独立窗口启动服务（`PORT=3100 npm start`）；
4. 用 `netsh` 开 Windows 防火墙入站 3100；
5. 打印访问地址：
   - 车间设备：`http://<本机局域网IP>:3100`
   - 本机：`http://127.0.0.1:3100`
6. 默认管理员账号 `admin / admin123`（首次启动控制台会提醒改密）。

> 脚本为**纯 ASCII**（避免 `cmd.exe` 按 GBK 解析 UTF-8 中文导致乱码闪退）；日志写 `start-local.log` 与 `server.log`，即使窗口闪退也能远程诊断。

## 三、手动启动（命令行）
```bash
cd workshop-app
npm install                 # 仅需一次，安装 express 等
PORT=3100 npm start         # 或 node --experimental-sqlite server.js
# 验证：
curl http://127.0.0.1:3100/api/health   # 返回 {"ok":true}
```

## 四、数据文件与备份
- 数据文件：`data/workshop.db`（WAL 模式，`-wal`/`-shm` 同目录）。**已被 `.gitignore` 排除，不进版本库。**
- 热备：`node --experimental-sqlite deploy/backup.js`（VACUUM INTO 到 `data/backups/`）。
- 回滚点示例：`data/backups/workshop_pre-master-clean_20260831063535.db`、`workshop_post-error_20260831064218.db`。
- 清空测试/演示数据回到主数据基线：`node --experimental-sqlite reset.js --yes`（清空业务表 + 删除 `t_` 测试账号，保留主数据基线）。

## 五、主数据测试残留清理规则
清除基础资料表内的测试 fixture（判定前缀）：
- 商品 `products`：**保留 `sp%`，删 `code/name NOT LIKE 'sp%'`**（sp=真实工厂资料；非 sp 如 P6_/P2_ 为测试）。
- 原料 `materials`：`code/name` 为 `ap%`/`e2e%`/`smk%` 均删。
- 供应商 `suppliers`：前缀在 **`name` 列**（非 code），`ap%`/`e2e%`/`smk%` 均删。
- 客户 `customers`：`name` 为 `smk%` 删（该表无 code 列）。
- 流程：停服务 → VACUUM INTO 备份 → `PRAGMA foreign_keys=OFF` 后 DELETE。

## 六、注意事项
- 服务常驻：关闭启动用的命令行主窗口，后台服务仍在；杀进程用 `netstat -ano | findstr :3100` 取 PID 后 `taskkill /PID <pid> /F`（Git Bash 用**单斜杠** `/PID`）。
- 勿误杀 CloudBase MCP 连接器进程（杀完会自启），判断服务是否停用以 `curl /api/health` 为准。
- 真机替换：开学后把整套目录拷到常开车间 PC，按第二节双击启动即可；数据随 `data/` 目录带走。
