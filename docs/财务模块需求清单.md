## 〇、一句话定位

把现有散落在 `finance_ledger` / `ar_*` / `ap_*` / `purchase_invoices` 的财务对象，**收敛到统一的"财务模块"**（左侧导航新增「财务」一级菜单），下设子页面；再补齐"账龄/月结/预算/银行账户/工资/固定资产/标准报表"等框架级缺口；最后用 RBAC 把"老板/管理/其他角色"在该模块里的读写边界钉死。

不重复造会计法/准则的轮子：复式记账、税务申报、审计接口**不重做**（也做不动），本系统是「**业务驱动的轻量财务**」，不是金蝶用友替代品。

## 三、推荐新增的子模块（按阶段划分）

### 📅 阶段一 · 高优先级（先做 1 个月 · 必做）

#### 1.1 财务概览页（聚合壳）
- **是什么**：原"资金往来"通用页升级为「财务概览」，是财务模块首页。
- **数据来源**：`finance_ledger` / `ar_invoices` / `ap_invoices` / `sales_orders` 实时聚合。
- **核心卡片**：
  1. 本月收入（实际收款 + 应收）
  2. 本月支出（实际付款 + 应付）
  3. 应收账款合计 + 账龄分布
  4. 应付账款合计 + 账龄分布
  5. 期末现金余额（来自 `bank_accounts`，见 1.2）
  6. 订单毛利 Top 5 / 毛损 Top 5
- **权限**：所有角色**只读**可见；老板/管理看完整数字，其他角色只看"自己相关"（如跟单只看自己客户的欠款）。
- **集成点**：不新增接口；用现有 `/api/finance/summary` + `/api/ar/summary/by-customer` + `/api/ap/summary/by-supplier` 组合。

#### 1.2 银行/现金账户管理 🆕
- **是什么**：多账户管理（对公户/私人户/现金），每次收付款关联到具体账户。
- **数据模型**（新表）：
  - `bank_accounts`（账户主档）：id, name（"工行对公"）, type（银行/现金）, account_no, opening_balance, current_balance（实时 SQL 算，不冗余）, currency, status, remark
  - `ar_receipts` / `ap_payments` 增列 `account_id`（外键 → `bank_accounts.id`，可空，老库 ALTER）
- **核心功能**：
  - 账户列表 + 余额（实时 = 期初 + 收款 − 付款）
  - 收/付款弹窗选账户
  - 账户调拨（账户 A → 账户 B 一笔对开转账，生成两条 ledger 记录）
  - 银行对账单导入（CSV/xlsx，按日期+金额+摘要匹配流水，差异标红）—— **v0 做简化匹配（按日期+金额精确匹配）**
- **权限**：写 = 老板/管理；读 = 老板/管理（其他人没必要看账户余额）。
- **集成点**：`ar.js` / `ap.js` 收付款接口增加 account_id；`finance_ledger` 增加 `account_id` 可空字段（自动归集的材料成本暂无账户，保留 null）。

#### 1.3 月结 / 期间管理 🆕
- **是什么**：财务期间（自然月），期间内可正常记账，期间锁定后只读；支持期末结转。
- **数据模型**（新表）：
  - `fiscal_periods`（期间主档）：id, period_code（"2026-09"）, start_date, end_date, status（开放/已锁定）, closed_at, closed_by（user_id）
- **核心功能**：
  - 期间列表（自动按月生成，已存在的跳过）
  - "锁定本期"操作：批量更新该月所有 `finance_ledger` / `ar_invoice` / `ap_invoice` 记录的 `period_id` 字段（需 ALTER 加列），并冻结
  - 锁定后任何人**不可修改**（包括老板/管理），需"反锁定"才可改
  - 期末结转：把损益类科目的余额转入"本年利润"（v0 简化：只算"收入合计 − 支出合计"，生成一条 `category='结转'` 的台账记录）
- **权限**：写（锁定/反锁定/结转） = 老板/管理；读 = 老板/管理。
- **集成点**：所有写财务对象的接口（`/api/finance` `/api/ar` `/api/ap`）在锁定期内直接 400 报错。

#### 1.4 账龄分析 🆕
- **是什么**：应收/应付账龄分段（0-30 / 31-60 / 61-90 / 90+ 天），按客户/供应商汇总。
- **数据模型**：不新增表；按 `ar_invoices.created_at` 与 `now` 的差值实时分组。
- **核心功能**：
  - 应收账龄表（按客户分组，列：客户 / 余额 / 0-30 / 31-60 / 61-90 / 90+）
  - 应付账龄表（按供应商分组，同上结构）
  - 总账龄统计卡片
- **权限**：读 = 老板/管理。
- **集成点**：`/api/ar/summary/by-customer` 升级返回 `age_buckets`；`/api/ap/summary/by-supplier` 同上。

#### 1.5 标准财务报表（基础三张表）🆕
- **是什么**：资产负债表 / 利润表 / 现金流量表。
- **数据模型**：不新增表；从 `finance_ledger` / `bank_accounts` 实时聚合。
- **核心功能**：
  - 资产负债表（简表）：资产（现金/应收/存货/固定资产）、负债（应付）、所有者权益
    - **重要限制**：存货估值 = 原料库存数量×最新价 + 成品库存数量×最新价（粗略）；固定资产 v0 不计（留 0 或不显示）
  - 利润表：营业收入 − 营业成本 − 期间费用 = 利润（按期间过滤）
  - 现金流量表：经营活动（收/付款汇总）+ 投资活动（设备采购可由 `machines` 派生）+ 筹资活动（v0 留 0）
- **权限**：读 = 老板/管理。
- **集成点**：`/api/finance/reports/{balance-sheet,income-statement,cash-flow}` 三个新接口；前端新增「财务 · 报表」子页。
- **风险提示**：这三张表**只是辅助**，不是给会计事务所/税务局用的合规报表，输出时要明确标注"内部管理报表"。

### 📅 阶段二 · 中优先级（看老板愿不愿付钱 · 1-2 个月）

#### 2.1 预算控制 🆕
- **是什么**：按月/季/年设预算，实际发生超预算预警。
- **数据模型**（新表）：
  - `budgets`（预算主档）：id, period_code, category（"物料"/"外发"/"人工"/"其他"）, amount, scope（"全厂"/"按部门"，v0 只做全厂）
- **核心功能**：
  - 预算录入页
  - 实际 vs 预算对比卡片
  - 超预算时**写**支出时弹窗警告（不强制拦截，老板确认即可）
- **权限**：写 = 老板/管理；读 = 老板/管理。
- **集成点**：写入 `finance_ledger` 时校验 `category` 累计 vs 当期 `budgets` 合计。

#### 2.2 凭证（包装式，不做完整复式记账）🆕
- **是什么**：把现有 `finance_ledger` 包装为"凭证"概念，每条记录 = 一张凭证（已有 `voucher_no`）。
- **数据模型**：复用 `finance_ledger`，加 `summary` 字段（摘要/事由，替代原 remark）。
- **核心功能**：
  - 凭证列表/查询/打印（v0 打印用浏览器 `window.print()`，不引入 PDF 库）
  - 凭证模板（销售收款/采购付款/材料归集/其他收/其他付）
- **不做**：借贷分录、试算平衡、科目映射。
- **权限**：写 = 老板/管理；读 = 老板/管理。
- **集成点**：不动后端逻辑，只在 UI 层加"凭证"概念 + 列表/打印样式。

### 📅 阶段三 · 低优先级（按需启动 · 2 个月+）

#### 3.1 固定资产卡片 + 折旧 🆕
- **是什么**：把现有 `machines` 表升级为"固定资产"概念，加资产卡片、折旧计算。
- **数据模型**（新表）：
  - `fixed_assets`：id, code, name, category, purchase_date, original_value, residual_rate, useful_life_years, depreciation_method（直线法/双倍余额）, current_value（实时算）, location, custodian, status
  - 关联 `machines.id`（一机一资产，ALTER 加 `asset_id`）
- **核心功能**：
  - 资产卡片（购入/折旧/处置全生命周期）
  - 月度折旧自动计算（每月 1 号跑一次，生成 `finance_ledger(category='折旧')` 记录）
  - 资产盘点（结合现有 `inventory-count` 模块思路）
- **权限**：写 = 老板/管理；读 = 老板/管理。
- **集成点**：月结（1.3）完成后才能做（折旧依赖期间）。

#### 3.2 工资/薪酬 🆕
- **是什么**：员工月度工资计算（基本+计件+加班+扣款），个税估算。
- **数据模型**（新表）：
  - `salary_profiles`：employee_id, base_salary, piece_rate（计件单价，可空），overtime_rate
  - `salary_sheets`（月度工资单）：id, period_code, employee_id, base, piece_amount, overtime, deductions, gross, tax, net, status
- **核心功能**：
  - 工资档案维护（员工管理页加入口）
  - 月度工资单生成（从 `production_log` 汇总产量×piece_rate）
  - 工资发放登记（关联到 `bank_accounts` 一笔付款，写入 `ap_payments` 或新表 `salary_payments`）
- **权限**：写 = 老板/管理；读 = 员工本人（只看自己）—— v0 简化为只老板/管理。
- **集成点**：依赖 C-4 工时归集（待办）；v0 不强求"工时"，只做"产量×工价"。
- **风险**：个税计算涉合规，建议接代账会计审核。

#### 3.3 税务辅助 🆕
- **是什么**：销项/进项发票登记，增值税申报辅助。
- **判定**：**v0 不做**。理由：(1) 合规风险（错报会罚款），(2) 老板有代账会计，(3) 工作量大。
- **可考虑 v1**：只做"开票信息登记"（客户名称、税号、税率、金额），不涉及申报。

## 四、统一设计原则（与项目整体对齐）

1. **不重做现有财务对象**：`finance_ledger` / `ar_*` / `ap_*` / `purchase_invoices` 全部保留，财务模块是**前端聚合壳 + 新增子模块**。
2. **派生数据实时算**：账户余额/账龄/毛利/报表数字全部**实时 SQL 聚合**，不冗余存。
3. **加列兼容老库**：所有 `ALTER TABLE` 走 `db.js` 的 `IF NOT EXISTS` 模式（参考现有 `migrateMachineWorkshops`），确保 `npm run reset` / 升级平滑。
4. **RBAC 不松动**：财务模块下所有**写**操作的资源角色 = `[老板, 管理]`，与现有 `finance / ar / ap` 保持一致。**新增"读"权限**考虑其他角色（员工/跟单/车间/品检）"只读自己相关"的场景。
5. **WAL + 事务**：所有写接口必须 `BEGIN/COMMIT/ROLLBACK`（参考 `ap_payments` 收款冲减），与现有约定一致。
6. **零原生依赖**：不引入 PDF 库 / 图表库 / 复杂导出。打印用浏览器自带，图表用现有 `<table>` + 简单 CSS。
7. **配套文档**：每个子模块上线时同步更新 `功能清单-当前版本.md` / `教学手册.md` / `USAGE.md`。

## 七、用户需要拍板的 8 个决策点

> 在动手出方案/排期之前，**先回答这 8 个问题**（有选项的建议直接选）。

1. **复式记账做不做？**
   - 做 → 需要会计科目表、试算平衡、工作量翻倍；
   - 不做 → 维持单式记账（现状），工厂够用。
   - **建议**：不做。

2. **银行对账单导入要不要做？**
   - 做 → 阶段一 1.2 内含简化匹配（按日期+金额）；
   - 不做 → 收付款手动选账户。
   - **建议**：做（v0 简化版）。

3. **期间锁定是软锁还是硬锁？**
   - 硬锁 → 锁定后任何人不能改（包括老板），需"反锁定"才可改；
   - 软锁 → 锁定后其他人不能改，老板仍可改。
   - **建议**：硬锁（财务严肃性）。

4. **账龄分析是否要分客户/供应商子表 + 总表？**
   - 是 → 标准三段式（0-30/31-60/61-90/90+）；
   - 否 → 简化为"超期/未超期"两段。
   - **建议**：是。

5. **标准财务报表是否要？**
   - 要 → 三张表都做（资产负债/利润/现金流）；
   - 部分 → 只做利润表（最常用）；
   - 否 → 不做。
   - **建议**：要，但内部管理用，明确标注非合规报表。

6. **预算控制是"全厂一类一个数"还是"按部门/产品"？**
   - 全厂 → v0 简单；
   - 按部门/产品 → v0 工作量×2。
   - **建议**：全厂 v0，按需升级。

7. **固定资产折旧是自动跑还是手动触发？**
   - 自动 → 每月 1 号定时任务（用 `node-cron` 或 `node:sqlite` + `setInterval`）；
   - 手动 → 在"月结"页点"计算折旧"按钮。
   - **建议**：手动（与期间绑定，避免"系统自己跑了一笔账"吓到老板）。

8. **工资模块是否本季必做？**
   - 必做 → 阶段三优先做；
   - 可选 → 阶段三按需启动；
   - 不做 → 维持人工算薪。
   - **建议**：可选（你 9/5 回学校，本季开发期够呛）。
