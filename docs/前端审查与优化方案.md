# 前端审查与优化方案（Impeccable 审计）

> 审查对象：`workshop-app` 前端（`public/`），原生 HTML/CSS/JS 单页应用，无框架、无构建、无 CDN，离线零依赖。
> 审查方法：Impeccable 设计语言「5 维审计（0–4 每维，/20）+ 反模式禁令清单 + 23 命令语义」；模式判定为 **Operate**（内部业务工具/仪表盘，可扫读、一致性、原生预期优先）。
> 约定：**先出报告，不直接改**。本报告给出 P0–P3 分级问题与按优先级排序的落地方案；实施阶段另起。

## 一、综合评分（/20）

| 维度 | 得分 | 说明 |
|---|---|---|
| Accessibility（可访问性） | 2 / 4 | 有 `focus-visible`、dialog 焦点陷阱/ESC/`aria-modal`、XSS 转义；但**禁用缩放**、表单 label 缺 `for`、登录框无 label、导航无 `aria-current`、个别徽章对比度临界 |
| Performance（性能） | 2 / 4 | 应用体积极轻、离线可用；但 **26 个独立 `<script>` 串行加载、无 `defer`、静态资源无缓存/版本号** |
| Theming（主题一致性） | 3 / 4 | 全面使用 CSS 变量、单光源；但 toast/登录层/导航激活态有**硬编码色绕过变量**，无深色模式 |
| Responsive（响应式） | 3 / 4 | 860px 抽屉、560px 表单单列、`stat-grid` 自适应良好；但**抽屉无遮罩关闭、触控目标 <44px、长表无 sticky 表头** |
| Implementation Integrity（实现完整性） | 3 / 4 | 页面注册体系 `Pages[page].render` 一致、`common.js` 复用度高、XSS 安全；但**内联 style 泛滥、表格/弹窗写法不统一、存在嵌套卡片** |
| **合计** | **13 / 20** | 位于「可接受，需大改」带。逐项修后可稳定到 17+ |

## 三、P0–P3 问题清单（按优先级）

### P0 · 阻断项（必须修，1 行级改动）
**P0-1 禁用页面缩放**
- 证据：`index.html:5` `<meta name="viewport" ... maximum-scale=1.0, user-scalable=no>`
- 影响：低视力车间工人无法放大；违反 WCAG 1.4.4 / 2.5.4；移动端也无法双指缩放。
- 改：`content="width=device-width, initial-scale=1.0"`（保留缩放能力）。

### P1 · WCAG AA 违例（应修）
**P1-1 表单 label 与控件不关联**
- 证据：`common.js:131` `<label>${f.label}</label>` 无 `for`；控件 `id="f_${name}"` 已存在但未关联。
- 影响：点击标签不聚焦输入框；屏幕阅读器不朗读关联。
- 改：`<label for="f_${f.name}">`。

**P1-2 登录框无 label / aria**
- 证据：`app.js:133-134` 两个 `<input>` 仅 `placeholder`，无 `<label>` 或 `aria-label`。
- 改：加 `aria-label="账号"` / `aria-label="密码"`（或视觉隐藏 label）。

**P1-3 导航激活态缺 `aria-current`**
- 证据：`app.js:108` `n.classList.toggle('active', ...)`，无语义属性。
- 改：同时 `n.setAttribute('aria-current', matched ? 'page' : 'false')`。

**P1-4 徽章对比度临界核验**
- 证据：`style.css:188-189` `.badge-low`(#c53030 on #fdecea)、`.badge-warn`(#b7791f on #fef3e2) 小字对比度需实测，可能 <4.5:1。
- 改：压深文字色或提亮底，确保 ≥4.5:1。

### P2 · 体验/一致性/性能（重要）
**P2-1 脚本零合并、无缓存**
- 证据：`index.html:65-92` 26 个 `<script>`；无 `defer`、无 `?v=` 版本号、服务器无缓存头。
- 影响：远程部署（云/Sealos）首屏 26 次请求；每次发布浏览器不刷新。
- 改：`defer` 全部脚本；静态资源加 `Cache-Control` + 文件名/查询版本号；中长期合并页面脚本为 1–2 个包（无构建可用简单 concat 脚本）。

**P2-2 内联 style 泛滥**
- 证据：`production-tasks.js` 多处 `style="margin-left:auto;display:flex;gap:8px"`、`min-width:140px` 等；各页重复造布局工具类。
- 影响：风格漂移、难统一维护。
- 改：抽取工具类 `.page-actions`（右对齐按钮组）、`.min-w`（最小列宽）、`.row` 已有；页内改用 class。

**P2-3 嵌套卡片**
- 证据：`production-tasks.js:161`(opCard `.card`) 嵌于 `:192`(`.card`) 内。
- 影响：双重阴影+内边距，视觉层级混乱。
- 改：内层改用轻量 `.sub-block`（仅 1px 边框、无阴影、小内边距）或 `border-top` 分隔。

**P2-4 表格/弹窗写法不统一**
- 证据：部分页用 `UI.table()`（`common.js:206`），`production-tasks.js`/`reports.js` 手搓 `<table>`；`openCreate` 手搓 modal 而 `openComplete/openReport` 用 `formModal`。
- 影响：行为不一致、重复代码。
- 改：列表统一走 `UI.table(headers, rows, {onRowClick})`；简单表单统一 `formModal`；仅极复杂（工序动态增删）保留自定义 modal。

**P2-5 移动端抽屉无遮罩**
- 证据：`style.css:278-284` 抽屉 `transform` 滑出，但内容区点击不关闭、无半透明遮罩。
- 影响：打开后误触内容、无路径返回。
- 改：抽屉展开时加 `.sidebar-backdrop`（fixed 半透明，点击关闭）。

**P2-6 触控目标 <44px**
- 证据：`style.css:119-146` `.btn` 高约 36px、`.btn-xs` `min-height:34px`。
- 影响：车间触控（可能戴手套）易误触。
- 改：移动端断点下 `.btn` 内边距加大至 ≥44px 高，或 `min-height:44px`。

**P2-7 长表无 sticky 表头**
- 证据：`style.css:172-177` 表头随滚动消失。
- 改：`thead th { position:sticky; top:0; background:var(--surface-2); z-index:1 }`（抽屉/卡片内注意包含块）。

### P3 · 抛光（可选）
- **P3-1 深色模式**：车间亮屏眩光，可加 `prefers-color-scheme` 或主题切换（CSS 变量已就绪，成本低）。
- **P3-2 死代码清理**：`icons.js:20` `AppIcons.schedule` 页面已删，移除。
- **P3-3 emoji 图标统一**：「📥 智能导入」改 SVG（`AppIcons` 已有风格）。
- **P3-4 硬编码色收口**：`style.css` toast(#1f2d3d/#276749/#9b2c2c)、`auth-overlay` 渐变、`nav-item.active(#e3eefb)` 改为 CSS 变量，便于主题切换。
- **P3-5 Toast 堆叠上限**：连续多条 toast 无上限，加最多 3 条/自动回收。

## 五、实施建议（顺序）
1. **先 A 后 B 再 C**：A 为合规底线、改动小风险低，立即做；B 提升日常可用性与可维护性，是性价比最高的投入；C 按演示/上线节奏取舍。
2. **每批配套验证**：A/B 改完跑 `npm test` + 浏览器手测（桌面 1280 / 平板 768 / 手机 375 三档断点、键盘 Tab 走查、缩放 200%）。
3. **不破坏现有身份**：本项目定位是「离线车间工具」，系统字体、实色背景、stat 卡片均为合理选择，优化只修缺陷、不重做视觉世界（遵循 Refinement preserves, redesign replaces）。
4. **评审对照**：实施后再按本表 5 维复评，目标 17+（优秀带下限）。
