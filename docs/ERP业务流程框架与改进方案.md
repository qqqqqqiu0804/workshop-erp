## 0. 摘要（给老板/决策层的一页纸）

本厂已经把"报价 → 销售 → MRP → 生产任务单 → 领料 → 报工 → 完工入库 → 发货 → 采购 → 品质 → 财务台账 → 报表"这条主流 ERP 主链路**基本跑通了**，比多数同规模（30 人左右五金加工厂）还在用 Excel + 纸质台账的状态领先一到两代。

但对照主流 ERP 的"标准闭环"，我厂系统目前有 **4 个真正的断点**和 **若干可轻量化补强的控制点**：

| 类别 | 关键项 | 现状 | 风险 |
|---|---|---|---|
| 🔴 断点 | 采购"三单匹配"与应付账期 | 采购单→到货入库，但无采购发票/应付管理 | 采购花了多少、该付多少、付没付，靠人脑对账 |
| 🔴 断点 | 销售开票与应收挂账 | 发货后无"开票/应收"环节，收入靠手工台账 | 哪笔订单收没收款、欠多少客户，无系统账 |
| 🔴 断点 | 材料成本自动归集 | 工单完工不自动算材料耗用，材料成本人工记 | 订单毛利率是"估"的，不是"算"的 |
| 🟡 断点 | 批次/序列号追溯 | 仅有 task_id 工序级追溯，无原料/成品批次号 | 客诉召回时无法定位"哪批料、哪批货" |
| 🟢 可补强 | 产能负荷/排程、移动端报工、月结对账、外发必检 | 均未做或弱 | 影响交付准点率与一线体验 |

**结论**：核心架构无需推倒重来。建议按"先堵 3 个财务断点 → 再补追溯与排程 → 最后上移动端"的路径，用 **3 个阶段（约 6–10 周）** 把系统从"能用"提升到"业财一体、可追溯、老板敢拿去报价"的水平。这比直接花 1.2 万/6 端口买厂商 SaaS 更贴合我厂已跑通的流程，且数据资产完全自有。

## 一、主流 ERP 标准业务流程调研

### 1.1 行业共识：ERP 不是"进销存"，是"三流合一"

多家来源（金蝶/用友/SAP/Odoo/简道云）一致强调：ERP 的核心价值是把**业务流、物流、资金流**实时打通，让前端业务单据（订单、入库、领料、完工、收付款）自动转化为财务信息，消除信息孤岛。这对应我们常说的"业财一体化"。

### 1.2 标准业务流按"闭环"划分（六大闭环 + 一个底座）

| 闭环 | 英文/简称 | 标准关键节点 | 核心控制点 | 典型 KPI |
|---|---|---|---|---|
| **销售到收款** | OTC (Order-to-Cash) | 报价→合同/订单→**信用检查**→排程备货→发货→**开票**→**收款核销**→对账 | 价格/额度审批、出库签收、发票校验、对账与收款匹配 | OTD 交付准点率、开票及时率、回款周期 DSO |
| **采购到付款** | P2P (Procure-to-Pay) | 请购/MRP→采购订单→到货→**来料质检 IQC**→入库→**供应商发票→三单匹配(PO/GR/发票)→应付→付款** | 供应商资格、到货质检、不合格处理、**三单匹配**、账期 | 到货合格率、供应商准时交付率、账期占用 |
| **计划到生产** | P2D (Plan-to-Produce) | 需求(订单/预测)→MPS→**MRP**→生产工单→领料→**工序报工**→质检→完工入库→**成本核算** | BOM/工艺路线准确率、产能负荷、领料审核、报工防重复、完工检验 | 计划达成率、工序直通率、OEE、WIP 周转 |
| **仓储物流** | WMS | 入库→上架→盘点→补货→出库→发运 | 库位策略、**批次/序列号**、FIFO 先进先出、ABC 分类、差异处理 | 拣选准确率、盘点差异率、周转天数 |
| **质量管理** | QMS | 来料 IQC→过程 IPQC→最终 FQC→**不合格品 NCR**→纠正预防 CAPA | 检验标准、抽样方案、判定规则、**隔离与放行**、追溯与批次 | 不良率、返工率、放行及时率、CAPA 关闭周期 |
| **财务过账** | FICO | 成本要素→生产领料/报工过账→**应收/应付**→总账结账→报表 | 科目映射、**期间锁定**、三单匹配、税务合规 | 月结周期、账龄>90天占比、毛利率 |
| **主数据底座** | Master Data | 物料/客户/供应商/BOM/工艺路线/工作中心/库位/会计科目 | 编码唯一、版本锁定、权责分明 | 主数据准确率 |

> 来源要点摘录：
> - SAP Business One 实践强调"工单成本核算"——材料、人工、制造费用穿透到每张工单，月结从 10+ 天压到 ≤3 天（MTC 实施数据）。
> - 简道云把控制点抽象为"触发事件 + ERP 对象 + 指标"的映射表，适合小厂照搬。
> - 金蝶云星空定位"成长型制造企业（年营收 5–50 亿）弹性之选"；SAP B1 定位中型（101–1000 人）；**两者都远超我厂体量**，我厂更接近"小微轻量化 ERP"档位。

### 1.3 小微轻量化 ERP 的共识（直接对标我厂）

多家针对"小微加工厂/30 人五金厂"的实践高度一致，核心结论：

1. **大厂定制 ERP 不适合小厂**：造价高（十几万起）、功能冗余（多车间排程/深度财税用不上）、需专职 IT、上手难。
2. **小厂 ERP 选型核心 = 够用、简单、省钱、贴合加工流程**。
3. **轻量化六大刚需**（长沙三为 / 优德普 / 伙伴云等）：原料采购管理、车间生产领料、成品入库、销售出库、全域库存管控、简易财务对账。完美适配"采购→领料→生产→入库→出货→对账"。
4. **移动端联动**是小厂提效关键：老板手机看库存/营收、业务员外勤报价录单、仓库扫码出入库。
5. **实施铁律**：先梳理瓶颈再定优先级；小步试点（一个部门/产品线）；数据准备（主数据标准化）；分岗培训；PDCA 持续优化。**避免"一步到位大而全"**。

## 二、通用业务流框架（抽象归纳）

把上面六大闭环 + 主数据底座，抽象成一张**通用框架图**（文字版）：

```
                    ┌──────────────── 主数据底座 ────────────────┐
                    │ 物料·客户·供应商·BOM·工艺路线·工作中心·库位·科目 │
                    └──────────────────────────────────────────┘
                                       │ 驱动
        ┌──────────────┬───────────────┴───────────────┬──────────────┐
        ▼              ▼                                 ▼              ▼
   【销售到收款】  【计划到生产】                    【采购到付款】   【仓储物流】
   报价→订单→    需求→MRP→工单→领料→报工→            MRP缺口→计划→  入库→上架→
   信用→备货→    质检→完工入库→(对接WMS)            订单→到货IQC→   盘点→补货→
   发货→开票→     ↑________成本________↓             入库→发票→三单   出库→发运
   收款→对账              ↑ 穿透                      匹配→应付→付款
        │                 │                                 │
        └─────────────────┴─────────────┬───────────────────┘
                                         ▼
                              【质量管理 QMS】
                          IQC→IPQC→FQC→NCR→CAPA
                                         │
                                         ▼
                              【财务过账 FICO】
                          应收/应付→总账→成本→月结→报表
```

**框架的三条主线（任何规模都适用）**：
- **订单主线（OTC）**：从客户要货到钱进口袋。
- **供应主线（P2P）**：从缺料到货到钱付出去。
- **制造主线（P2D）**：把料变成货，并把成本算清。

三条主线在**库存**交汇，在**财务**汇账，在**质量**受控。这就是"通用业务流框架"。

## 三、适配我厂体量的推荐流程（轻量化推导）

### 3.1 我厂画像（用于裁剪的硬约束）

| 维度 | 我厂实际 | 对流程的影响 |
|---|---|---|
| 规模 | ~26 人（生产/品质 18 + 管理 8） | 无专职 IT、无复杂组织层级 |
| 设备 | 23 台（自动车 12 + 走心机 11） | 产能有限，排程要"看得清"但不必 APS |
| 组织 | 2 车间、5 工序组（自动车/走心机/品检/包装/管理） | 工艺路线相对固定 |
| 模式 | 接单生产 MTO、多品种小批量（精密五金/CNC） | 预测/APS 优先级低，按单追溯是刚需 |
| 客户 | 国内 + 国外 | 需报价→转单、客户数据隔离 |
| 外发 | 热处理/氧化/电镀等工序外发 | 外发回收检验是重点 |
| 决策 | 老板 + 管理岗拍板 | 审批流可极简，但要"老板手机能看" |
| 一线 | 车间电脑/平板操作 | 移动端是加分项，非必须 |

### 3.2 轻量化六原则（裁剪标准）

1. **单工厂单组织**：不做多法人/多工厂协同、合并报表。
2. **MTO 为主，预测后置**：MRP 由销售订单驱动即可，MPS/APS 排程先不做重的。
3. **按订单成本核算**：不做"标准成本 vs 实际成本"全套，但要把**材料/人工/外发/制造费用按订单归集**做透。
4. **控制点抓大放小**：保留"三流合一、批次追溯、关键节点审批"；砍掉复杂信用额度、多层级审批、精细产能排程。
5. **移动优先**：老板驾驶舱已做（手机只读），下一步让一线也能移动报工/领料。
6. **渐进上线**：先核心闭环（接单→生产→发货→对账），再补强（追溯/排程/移动）。

### 3.3 推荐给我厂的"够用流程"（对照主流做减法）

| 流程环节 | 主流 ERP 标准做法 | **我厂推荐做法（减法后）** | 取舍理由 |
|---|---|---|---|
| 报价 | 多版报价、审批流 | 报价单→转销售单（保留） | 小厂一版够用，转单流转保留 |
| 接单 | 信用检查 + 多级审批 | 建单即可，加"订单复核"轻节点 | 客户少、老板熟，免信用额度 |
| 计划 | MPS + MRP + APS | **MRP（物料净需求）+ 任务单** | 不做产能精细排程，加"负荷看板"即可 |
| 领料 | 按工单配料、条码 | 按 BOM 展开领料单（已做） | 保留 |
| 报工 | 工序报工 + 工时 | 工序报工（产量），**后补工时** | 先把产量追溯做扎实 |
| 质检 | IQC/IPQC/FQC/CAPA | 进料/过程/成品/外发四类（已做） | 保留，补"外发回收必检" |
| 完工 | 自动成本卷算 | 完工入库（已做）+ **材料成本自动归集**（待补） | 成本自动算是核心缺口 |
| 发货 | 发货 + 开票 + 应收 | 发货（已做）+ **开票/应收登记（待补）** | 应收是资金流断点 |
| 采购 | 订单→IQC→入库→发票→三单匹配→应付→付款 | 订单→到货入库（已做）+ **发票/应付/付款登记（待补）** | 应付是资金流另一断点 |
| 库存 | 库位 + 批次/序列号 + FIFO + 盘点 | 库位 + 盘点（已做）+ **批次号（待补）** | 精密件追溯需批次 |
| 财务 | 自动凭证 + 月结 + 账龄 | 独立台账（已做）+ **应收应付账期 + 月结视图（待补）** | 让老板看见"谁欠我、我欠谁" |
| 报表 | BI 多维 | 报表中心 + 驾驶舱（已做） | 保留 |

**结论**：主流 ERP 的"骨架"我厂已经具备 80%，缺口集中在**资金流闭环（应收/应付）**和**成本自动归集**这两个财务断点，以及**批次追溯、负荷看板、移动端**三个增强点。

## 四、现有系统实际流程梳理与逐项对比

### 4.1 现有系统已实现的流程（基于 workshop-app P0–P12）

| 主线 | 已实现环节 | 实现位置 |
|---|---|---|
| 销售 OTC | 报价单(P10) → 销售订单(P2) → 生成计划触发 MRP(P5) → 发货(P2 deliver) | 完整前半段 |
| 计划 P2D | MRP 净需求(P2/P5) → 自制任务单草稿(P5) → 生产任务单(P1) → 领料备料(P6) → 逐工序报工(P1) → 完工入库(P1) | 完整 |
| 采购 P2P | 采购计划(P5) → 采购单(P 采购管理) → 到货登记入库(P) | **到"入库"为止** |
| 库存 WMS | 原料库存 / 成品库存(P0) / 库位 / 盘点 | 较完整，无批次 |
| 质量 QMS | 进料/过程/成品/外发回收检验(P3) | 有记录，未强制串流程 |
| 财务 FICO | 独立台账(P4) + 按订单成本毛利(P4) + 报表(P8) + 驾驶舱(P9) | **台账手工，成本半自动** |
| 主数据 | 商品/物料/客户/供应商/成品库存导入(P12) + RBAC(P11) | 完整 |

### 4.2 逐项对比与差异点（核心交付物）

| # | 流程环节 | 推荐做法 | 现有系统实现 | **差异 / 问题** | 严重度 |
|---|---|---|---|---|---|
| 1 | 销售开票 + 应收 | 发货后生成应收、跟踪回款 | 发货只扣成品库存，**无开票/应收对象**；收入靠财务台账手工记 | 🔴 资金流断点：不知道"哪笔单欠多少钱、收没收" | 高 |
| 2 | 采购发票 + 三单匹配 + 应付 | PO/入库/发票三单匹配 → 应付 → 付款 | 采购单→到货入库，**无发票/应付/付款登记** | 🔴 资金流断点：采购花销与付款无系统账 | 高 |
| 3 | 材料成本自动归集 | 工单领料自动算进订单成本 | 材料成本**人工在台账记"物料"支出**，未从 BOM 领料自动派生 | 🔴 成本断点：毛利率是"估"的 | 高 |
| 4 | 批次/序列号追溯 | 原料/成品批次号 + FIFO + 召回追溯 | 仅 task_id 工序级追溯，**无批次号** | 🟡 精密件客诉召回无法定位批次 | 中 |
| 5 | 产能负荷 / 排程 | 任务单负荷看板、瓶颈预警 | MRP 只算物料，**无产能/机台负荷** | 🟡 23 台机排产靠人脑，易过载/闲置 | 中 |
| 6 | 外发回收必检 | 外发回收 → 强制 IQC → 入库 | 外发回收入库(P3)，但**未强制关联品质检验** | 🟡 外发件可能未检就入成品库 | 中 |
| 7 | 移动端一线操作 | 扫码报工/领料、手机录单 | 驾驶舱手机**只读**；一线报工/领料需电脑/平板 | 🟢 体验短板，非阻塞 | 低 |
| 8 | 月结对账 / 账龄 | 期间锁定 + 应收应付账龄 | 台账连续记账，**无月结/账龄视图** | 🟢 老板看"时段应收应付"需手动筛 | 低 |
| 9 | 安全库存驱动补货 | 低于安全库存自动建议采购 | 有安全库存预警（报表），但**MRP 不读安全库存** | 🟢 补货建议仍靠人工看预警 | 低 |
| 10 | 工时 / 人工成本 | 报工记录工时 → 算人工成本 | 报工只记产量，**不记工时** | 🟢 人工成本目前无法按单归集 | 低 |

### 4.3 问题归类

- **A 类 · 资金流断点（必须补）**：#1 应收、#2 应付、#3 成本归集。这三项不补，"业财一体"就是一句空话，老板报价时毛利率仍靠拍脑袋。
- **B 类 · 追溯与排程（建议补）**：#4 批次、#5 负荷、#6 外发必检。影响质量可靠性与交付准点率。
- **C 类 · 体验与辅助（可选补）**：#7 移动端、#8 月结、#9 安全库存驱动、#10 工时。锦上添花，按资源排期。

## 五、改进方案（调整建议 + 实施路径，无代码）

> 以下均为**业务/流程层面的方案描述**，不含任何代码实现。落地时再由开发按现有架构（node:sqlite + 原生前端）迭代。

### 5.1 总体策略

**不推倒、不重做、补闭环**。现有 P0–P12 主链路是资产，改造只做"增量补强"：在已有数据模型上**新增资金流对象**（应收/应付/发票/付款）与**成本自动归集规则**，并把"批次、负荷、外发必检"作为流程约束嵌进去。

### 5.2 分阶段实施路径

#### 阶段一（P0 级，约 2–3 周）：堵住三个资金流断点

| 改进项 | 方案思路 | 预期收益 |
|---|---|---|
| **应收管理** | 销售发货后自动生成"应收单"（关联 SO、金额=发货额）；支持登记"收款"冲减；列表按客户显示"应收余额 / 已收 / 未收"。 | 老板随时看"客户欠我多少" |
| **应付管理** | 采购到货入库后生成"应付单"（关联 PO、金额=实收×单价）；支持登记"付款"冲减；列表按供应商显示"应付余额"。 | 采购花销与付款一目了然 |
| **三单匹配（轻量）** | 引入"采购发票"登记对象，与 PO + 入库单做金额/数量比对，差异标红。小厂可先"可选登记"，不做强制拦截。 | 杜绝"票不齐就付款" |
| **材料成本自动归集** | 领料备料(P6)确认发料时，按实领量 × 物料最新价，**自动写一笔"物料"支出进财务台账并关联 SO**（经任务单反查来源 SO）。 | 订单毛利率从"估"变"算" |

> 阶段一完成后，"报价→接单→生产→发货→收款"与"缺料→采购→到货→付款"两条资金流闭环打通，系统从"生产管理"升级为"业财一体"。

#### 阶段二（P1 级，约 2–4 周）：补强追溯与排程

| 改进项 | 方案思路 | 预期收益 |
|---|---|---|
| **批次/序列号** | 原料入库、成品完工入库支持"批次号"字段；库存流水带批次；FIFO 出库建议。精密件可一物一码。 | 客诉可反向追溯"哪批料→哪批货→哪台机→哪个工单" |
| **产能负荷看板** | 基于 23 台机 + 5 工序组，汇总"进行中任务单"在各机台/工序组的计划负荷 vs 可用产能，超阈值标红。 | 排产能看见瓶颈，少接/缓接过载订单 |
| **外发回收必检** | 外发单"回收"操作前，强制要求先有该外发单的"外发回收检验"合格记录，否则拦截入库。 | 外发件质量兜底 |

#### 阶段三（P2 级，约 2–3 周）：体验与辅助增强

| 改进项 | 方案思路 | 预期收益 |
|---|---|---|
| **移动端一线** | 报工/领料做成手机/PDA 友好页（复用现有 API），支持扫码识别机台/任务单/物料。 | 车间告别"跑回电脑录数据" |
| **月结与账龄视图** | 财务新增"按期间"汇总（应收账龄、应付账龄、期间收支），支持月度结账视图。 | 月底对账从几天变几分钟 |
| **安全库存驱动 MRP** | MRP 计算时纳入各物料安全库存，净需求 = 需求 − 库存 + 安全库存。 | 补货建议更稳，少断料 |
| **工时与人工成本** | 报工增加"工时"字段，按工时 × 工时单价归集人工成本进订单。 | 成本四维（料/工/外发/费）齐全 |

### 5.3 优先级与资源建议

- **必做（本季）**：阶段一全部（A 类 3 项）。这是"业财一体"的门槛，投入小、杠杆大。
- **应做（下季）**：阶段二（B 类）。客户对精密件追溯要求高时升为必做。
- **选做（按需）**：阶段三（C 类）。资源宽裕或老板要"更顺手"时排期。

### 5.4 与"自研 vs 买厂商 SaaS"决策的关联

本分析直接支撑你的选型判断：

- **我厂已自研跑通 80% 主链路**，且数据完全自有、零年费、贴合五金加工流程——这是买 1.2 万/6 端口 SaaS 给不了的优势（SaaS 数据在厂商侧、流程是它定的、超 6 端口要加钱）。
- **缺口（资金流 + 追溯）是通用需求**，自研补这部分的边际成本，远低于买 SaaS 后还要"先迁数据、再改流程、再培训"的总成本。
- **建议立场**：以自研为主、持续迭代阶段一→三；仅在"移动端/PDA 硬件 + 扫码枪"等需要外部集成时，考虑局部采购或外包，而非整体换厂商系统。
